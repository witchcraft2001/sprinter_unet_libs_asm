# Справочник UNETLD

`include/unetld.asm` — это код-include для SjASMPlus, который читает
переменную среды `NET`, превращает её значение в имя DLL сетевого бекенда,
загружает эту DLL через
[libman](https://github.com/witchcraft2001/sprinter-libman), проверяет её
ABI и возможности и даёт тонкую обёртку над `LIBMAN.l_call` плюс жизненный
цикл `NETINIT`/`NETDONE`.

Сам контракт UNET (номера функций, регистровые соглашения, коды ошибок,
биты возможностей) описан в [docs/UNETAPIRU.md](UNETAPIRU.md). Этот
документ покрывает только слой выбора и загрузки.

## Выбор бекенда

`NET` должна содержать 3–4 символа из `[A-Z0-9]` (нижний регистр
принимается и приводится к верхнему автоматически). Имя DLL строится прямо
из этого значения:

| `NET` | Загружаемая DLL |
| ----- | --------------- |
| `RTL` | `UNETRTL.DLL`   |
| `WIZ` | `UNETWIZ.DLL`   |
| `3COM`| `UNET3COM.DLL`  |

`WIFI` — единственное исключение, алиас на тег `ESP` (`UNETESP.DLL`) для
обратной совместимости с существующими инструментами (`NETUP` публикует
`NET=WIFI`). Если нужно добавить ещё один алиас, см. `ALIAS_TABLE` в конце
`unetld.asm` — обычному новому бекенду, который следует конвенции
«значение `NET` = тег DLL», правки кода вообще не нужны, достаточно
положить рядом соответствующий `UNET<тег>.DLL`.

## Два режима размещения состояния

Выберите **один** до `INCLUDE "unetld.asm"`:

### Простой режим (по умолчанию)

Просто подключите файл. ~315 байт состояния UNETLD (handle, возможности,
слово ABI, байты ошибки/статуса, разрешённый тег и имя DLL, 32-байтный
буфер `l_info` и 256-байтный буфер значения переменной среды) эмитируются
обнулённой областью прямо внутри образа EXE. Больше ничего не требуется —
любую точку входа можно вызывать сразу. Плата: собранный EXE примерно на
315 байт больше, чем необходимо. Так сделан `examples/netinfo`.

### Компактный режим

```asm
        DEFINE  UNETLD_STATE_BASE <адрес>
        INCLUDE "unetld.asm"
```

В образ не эмитируется ни байта состояния — каждая метка состояния
`UNETLD.*` становится смещением `EQU` от `<адреса>`. Этот адрес должен
указывать на память, которой программа действительно владеет во время
работы (не переиспользуемую ничем другим, в окне, которое остаётся
отображённым, ниже `0xC000`), и она **не** обнуляется при загрузке EXE —
поэтому нужно **обязательно** один раз вызвать `UNETLD.RESET` до любой
другой точки входа, чтобы обнулить её самостоятельно.

`examples/ping`, `examples/httpget` и `examples/udpecho` используют этот
режим с фиксированным адресом рабочей области (`WORK_BASE EQU 0B000h`),
расположенным заведомо выше, чем может закончиться их код; это
подстраховано директивой `ASSERT CODE_END <= WORK_BASE`, размещённой
*после* подключения `unetld.asm`/`libman.asm` (их код — тоже настоящие,
эмитируемые байты; в этом режиме «бестелесно» только *состояние* UNETLD).
Не вычисляйте базовый адрес из текущей позиции `$` до подключения
`unetld.asm`: сам `unetld.asm` эмитирует после этой точки ещё код, и
адрес, вычисленный слишком рано, наложится на него. Либо берите
фиксированную константу, как в примерах, либо поставьте метку после всех
нужных программе `INCLUDE` и используйте её.

В любом случае доступна константа `UNETLD.STATE_SIZE`, если нужно
рассчитать раскладку в другом месте, а `UNETLD.STATE_END` — первый адрес
за состоянием UNETLD, удобный как база для собственных буферов, как
сделано во всех трёх компактных примерах.

## Точки входа

Все вызываются как `CALL UNETLD.<имя>`. Регистровые контракты следуют
конвенции UNET: аргументы в A/DE/IX/IY, CF сигнализирует о жёсткой ошибке,
остальное — в регистрах или состоянии.

### `UNETLD.RESET`
Обнуляет весь блок состояния. Обязателен один раз, до всего остального,
если используется `UNETLD_STATE_BASE`. Безвреден в простом режиме. Можно
вызывать повторно после `UNLOAD`. Выход: CF=0.

### `UNETLD.SELECT`
Читает `NET`, проверяет и приводит к верхнему регистру, разрешает алиасы,
строит имя DLL.
Вход: —
Выход: CF=0, заполнены `UNETLD.NET_TAG` и `UNETLD.DLL_NAME`.
CF=1, A=`UNETLD_E_NOENV` (не задана/пуста) либо `UNETLD_E_BADVALUE`
(неверная длина или набор символов — исходное значение остаётся в
`UNETLD.ENV_VALUE`).

### `UNETLD.LOAD`
Загружает DLL, выбранную `SELECT`, и проверяет её.
Вход: A = целевое окно, 1 (`0x4000`) или 2 (`0x8000`). **Никогда 3.**
Требует предварительно успешного `SELECT`.
Выход: CF=0, HL=handle, DE=возможности, IX=слово ABI (также сохранены в
`UNETLD.HANDLE`/`CAPS`/`ABI`).
CF=1, A=`UNETLD_E_LOAD` (не сработал `l_load` libman — см.
`LIBMAN.l_reason`/`l_dss_error`/`l_load_stage`/`l_init_status`, активны при
`LIBMAN_DIAGNOSTICS`), `E_INFO` (не сработал `l_info`), `E_NAME` (имя L1 у
DLL не начинается с `UNET` + ваш тег), `E_CALL` (ошибка диспетчера или
не-OK статус при вызове `GETCAPS`) либо `E_ABI` (старший байт слова ABI из
`GETCAPS` не совпал с `HIGH(UNET_ABI_VERSION)`).
При любом CF=1 здесь, **кроме** `E_LOAD`, handle DLL уже открыт — вызовите
`UNLOAD` перед повторной попыткой или выходом.

### `UNETLD.CALL`
Диспетчеризует один вызов функции UNET в загруженной DLL. Всё тело:
`LD HL,(UNETLD.HANDLE) / JP LIBMAN.l_call`.
Вход: B = `UNET_FN_*`, аргументы в A/DE/IX/IY согласно `unet.inc`.
Выход: CF=1 только при ошибке диспетчера libman/DSS; иначе в A — статус
UNET `NERR_*` (проверять A, а не CF), результаты в A/DE/IX/IY.
Handle — обычный handle libman: вызывать с ним
`LIBMAN.l_call`/`l_info`/`l_free` напрямую, минуя эту обёртку, можно в
любой момент.

### `UNETLD.NETSTART`
Проверяет конфигурацию и инициализирует бекенд. Обратите внимание: сеть
эта функция *не* поднимает — это делает заранее кит соответствующего
бекенда (`NETUP` либо `NETCFG`/`IFUP`), он же публикует переменные
`NET_*`. `NETSTART` лишь готовит DLL к работе с уже поднятой сетью:
`STATUS(0xFF)` (намеренно не трогает железо — только подтверждает, что
конфигурация опубликована), принимая `NERR_OK` или `NERR_NONET`, затем
`NETINIT`, который инициализирует драйвер и его железо (находит UART или
пробует карту, включает управление потоком, режим multi-connection).
Вход: — Требует предварительно успешного `LOAD`.
Выход: CF=0, A=0, установлен флаг `NETINIT`.
CF=1, A=`UNETLD_E_CALL` (ошибка диспетчера), `E_STATUS` (`STATUS` вернул
не `NERR_OK` и не `NERR_NONET`) либо `E_NETINIT` (`NETINIT` вернул не-OK
статус). Код `NERR_*` остаётся в `UNETLD.LAST_STATUS`.

### `UNETLD.REQUIRE`
Проверка возможностей.
Вход: DE = требуемая маска `UNET_CAP_*` (биты можно комбинировать).
Выход: CF=0, если все запрошенные биты установлены в `UNETLD.CAPS`; иначе
CF=1. Не трогает `UNETLD.ERROR` — об отсутствующей возможности
потребитель сообщает сам.

### `UNETLD.UNLOAD`
Идемпотентное сворачивание, безопасное на любом пути ошибки и при
повторных вызовах: `NETDONE` (если `NETINIT` был успешен), затем `l_free`
(если DLL загружена), оба best-effort, после чего весь блок состояния
обнуляется через `RESET`.
Выход: всегда CF=0.

## Состояние (только для чтения, имена меток одинаковы в обоих режимах)

| Метка | Размер | Значение |
| --- | --- | --- |
| `UNETLD.HANDLE` | 2 | handle загруженной DLL в libman |
| `UNETLD.CAPS` | 2 | битовая маска возможностей из `GETCAPS` |
| `UNETLD.ABI` | 2 | слово ABI из `GETCAPS` (major\<\<8\|minor) |
| `UNETLD.ERROR` | 1 | последний код `UNETLD_E_*` |
| `UNETLD.LAST_STATUS` | 1 | последний `NERR_*` от `STATUS`/`NETINIT` |
| `UNETLD.FLAGS` | 1 | бит0 = DLL загружена, бит1 = `NETINIT` успешен |
| `UNETLD.NET_TAG` | 5 | разрешённый тег, ASCIIZ, до 4 символов |
| `UNETLD.DLL_NAME` | 13 | `"UNETxxxx.DLL",0` |
| `UNETLD.DLL_INFO` | 32 | приёмник для `l_info` libman |
| `UNETLD.ENV_VALUE` | 256 | исходное/приведённое к верхнему регистру значение `NET` |
| `UNETLD.STATE_SIZE` | — | суммарный размер блока выше |
| `UNETLD.STATE_END` | — | первый свободный адрес за блоком |

## Коды ошибок (`UNETLD_E_*` — обычные глобальные константы, без префикса модуля)

| Константа | Значение | Кем устанавливается |
| --- | --- | --- |
| `UNETLD_E_NOENV` | 1 | `SELECT` — `NET` не задана или пуста |
| `UNETLD_E_BADVALUE` | 2 | `SELECT` — `NET` не 3–4 символа из `[A-Z0-9]` |
| `UNETLD_E_LOAD` | 3 | `LOAD` — не сработал `l_load` |
| `UNETLD_E_INFO` | 4 | `LOAD` — не сработал `l_info` |
| `UNETLD_E_NAME` | 5 | `LOAD` — несовпадение имени DLL |
| `UNETLD_E_CALL` | 6 | `LOAD`/`NETSTART` — ошибка диспетчера или плохой статус `GETCAPS` |
| `UNETLD_E_ABI` | 7 | `LOAD` — неподдерживаемая старшая версия ABI |
| `UNETLD_E_STATUS` | 8 | `NETSTART` — неожиданный результат `STATUS(0xFF)` |
| `UNETLD_E_NETINIT` | 9 | `NETSTART` — не сработал `NETINIT` |

## Загрузка собственных DLL рядом с UNET

UNETLD не оборачивает и не прячет libman — программа подключает
`libman.asm` сама, поэтому полный API
`LIBMAN.l_load`/`l_call`/`l_info`/`l_free` доступен её собственному коду
для её собственных библиотек (шрифты, графика, ...) параллельно с
UNET-бекендом. Handle, который возвращает `UNETLD.LOAD`, — обычный handle
libman в той же таблице, что и ваши, а `UNETLD.UNLOAD` освобождает только
его и никогда не трогает библиотеки, загруженные вами.

Помнить нужно о двух вещах:

- **`LIBMAN_MAX_LIBS`** — это ваш DEFINE, а не UNETLD. Примеры ставят 1,
  потому что не грузят ничего, кроме UNET-DLL; поднимите его до числа
  DLL, которые держите загруженными одновременно (графическая сборка
  weather-forecast использует 3: UNET + GFX320 + AFNT320).
- **Окна:** libman при каждом `l_call` сам подключает в окно страницу
  нужной DLL, поэтому несколько DLL могут делить окно 1, как это сделано
  в weather-forecast. Специфичные для UNET правила при этом остаются в
  силе: окно 3 для UNET-DLL запрещено, а буферы, передаваемые в функции
  UNET, должны лежать вне её окна.

## Замечание про `dss.inc`

`include/dss.inc` — небольшой, намеренно неполный набор констант DSS:
только то, что используют `unetld.asm` и примеры. Это не слияние копий
`dss.inc` из `sprinter_wifi/network` и `sprinter-rtl8019a` (те разошлись и
конфликтуют по части имён). Сам `unetld.asm` обращается только к `DSS`,
`DSS_ENVIRON` и `ENV_GET`, которые есть во всех известных вариантах,
поэтому `unetld.asm` безопасно использовать вместе с более полным
`dss.inc` любого бекенда. `examples/common/conutil.asm` использует ещё
несколько имён из нашего `dss.inc` и является обвязкой только для
примеров, а не частью API для потребителей.

## Добавление бекенда

1. Положите `dll/UNET<ТЕГ>.DLL` (собранный под замороженный ABI из
   `unet.inc`) и добавьте запись в `dll/manifest.json`.
2. Если значение `NET` должно отличаться от тега DLL (как `WIFI` →
   `ESP`), добавьте одну строку в `ALIAS_TABLE` в `unetld.asm`. В
   остальном ничего не меняется — как только инструмент настройки нового
   бекенда опубликует `NET=<ТЕГ>` (так же, как `NETUP` публикует
   `NET=WIFI`, а `NETCFG`/`IFUP` — `NET=RTL`; вручную `NET` пользователи
   не задают), всё описанное выше просто работает.
